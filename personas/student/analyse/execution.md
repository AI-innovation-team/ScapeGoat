# 核心命题

student 的执行模式是高责任、高细节投入、低求助、方向感易波动。他在具体实现和局部优化上有耐力，也愿意返工和自我修正；但因为对他人成本高度敏感，加上全局骨架感较弱，容易自己扛太久、同步太晚，并在局部细节中消耗掉整体推进能力。

# 机制展开

他的执行起点高度依赖任务本身要求，不是天然先拆解、先定义价值，而是根据任务框架进入工作。出现方向反复时，既可能是后来想清楚了，也可能是一开始就没想清楚。这说明他并非抗拒修正，而是经常在推进中才逐步看见真正的问题结构。

对返工，他会先看自己判断是不是有问题，说明其默认执行伦理仍是对事负责而非推责。最大的问题在于协作成本敏感。因为非常不想麻烦别人，他会延迟同步、延迟求助、自己扛很久。这样做短期减少摩擦，长期却会把风险集中到自己身上。

他也清楚自己“做事细，但容易沉到局部细节，没有方向感”。这说明短板已被本人准确识别，只是仍在重复。

# 案例支撑

- 接任务时会先看“任务本身要求”。
- 方向会反复推翻，原因既有“想得更清楚了”，也有“一开始没有想清楚”。
- 返工时会先归因自己的判断是否不好。
- 对别人的时间和劳动成本“非常会”敏感。
- 明确承认“既希望自由推进，又不想被流程和协作拖住”的矛盾很重。
- 自己总结合作中的优点与麻烦是“做事细，但容易沉到局部细节，没有方向感”。

# 与其他层的关系

这层直接受 cognition 支配，也明显受 formation 中“不麻烦别人”和 defenses 中自我吸收式防御影响。priorities 中把他人期待放得较高，也会加剧其不愿给他人添麻烦的执行方式。

# 预测规则

- 面对模糊任务时，他会先进入局部推进，之后再逐步修正方向。
- 当协作需要及时暴露问题时，他可能因不想打扰而延后同步。
- 当某个局部能被持续优化时，他容易在该处投入过多，牺牲整体推进节奏。
- 当返工发生时，他更可能自我检讨，而不是先指出外部条件的问题。

# 这层的稳定性分析

这层稳定，因为它与他的优势绑定得很深: 细、能扛、愿意修、少麻烦人。外界通常会奖励这些表现，却不会立刻惩罚其晚同步和方向感不足。除非任务复杂度高到迫使他必须先做全局设计，否则这套执行模式仍会持续复现。
