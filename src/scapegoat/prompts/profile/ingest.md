# 语料 → 画像抽取

从语料（任意文档、对话转写）中抽取心理画像证据，生成或增量更新画像目录。本流程与访谈/测评共用同一套维度框架（见 `init.md` 的 11 维定义）和写入契约（见 `merge_rules.md`，必须先读）。

## 输入

- **subject_id** 与画像目录位置（`profiles/<subject_id>/`，或用户指定的其他目录）。
- **归一化语料**：由 `scapegoat profile corpus <files...>`（或 MCP `normalize_corpus`）产出的 markdown 块。JSON 对话已转成 `speaker: text` 转写；文档为原文。
- **说话人映射**：对话语料必须先向用户确认哪个 speaker 是画像对象（如 `teacher` = 被画像者），其余说话人只作为情境。**不确认不开始抽取。**

## 抽取流程

### 第一遍：证据扫描

通读语料，按 11 个维度收集**原始证据**。每条证据记录：

```
[维度] 引文或事件（≤2句原文） → 初步解读
```

只收"此人自己说的话/做的事"，不收他人对他的评价（他人评价只能作为待验证线索）。对话语料重点看：他如何布置任务、如何回应异议、如何解释失败、他反复讲的道理、他在利益冲突处的选择。

### 第二遍：反转校验

对每条有情感色彩或利益相关的证据做双重解读（同 init.md 的反转解读机制）：字面解释 vs 更不温和的结构性解释。语料模式下无法向用户逐条求证，规则是：**单一证据取字面，重复出现的模式取结构**——同类行为出现 ≥2 次才允许上升为结构性断言，否则标注低置信度。

### 第三遍：生成预测规则

把通过校验的证据压缩成 `情境 → 行为` 规则，按维度归档。每条规则挂上证据指针（语料批次 + 简短引文）。

## 写入

- **画像不存在**：按 init.md 的文件结构生成 12 个文件。素材覆盖不到的维度照常建文件，写明"本维度暂无语料证据"，不编造。
- **画像已存在**：逐维度执行 merge_rules.md 的合并规则（整合、禁纯追加）。这就是持续学习入口——每来一批新语料，重复本流程即可。
- 写入完成后：更新来源记录行，运行字节预算校验（`scapegoat profile budget <subject_id> --strict`），超预算按契约压缩。
- 最后向用户汇报：新增/修改了哪些维度的哪些规则、发现的冲突及处理方式、预算校验结果，并提示"画像已更新，如需用于 rollout 请重新 freeze"。
