# 画像写入契约：最小字节原则

所有向画像目录（`profile.md` + `analyse/*.md`）写入内容的流程——无论素材来自语料、访谈还是测评——必须遵守本契约。目标：**用准确、不冗余的语言把结构表达清楚**。字节是成本，预测力是收益；每一句都要挣回自己的字节。

## 一、句子准入标准

一句话能写进画像，当且仅当同时满足：

1. **可预测**：能改写成「在情境 X 下，他会做 Y」。写不出 X→Y 的句子（如"他比较复杂"、"他有自己的考量"）不许出现。
2. **有证据**：能指向至少一条具体素材（对话片段、事件、测评作答）。案例只保留**证据力最强的 1–2 个**，其余删除——案例是证据不是修辞。
3. **不重复**：同一洞见在整个画像中只出现一次，放在最相关的维度文件里；其他文件如需引用，用一句话指路（"见 priorities"），不复述。

## 二、合并规则（增量更新时）

画像已存在时，新信息**必须整合，禁止纯追加**：

- **重合**：新证据支持已有规则 → 不新增文字；如新证据更强，替换旧案例。
- **细化**：新证据让已有规则更精确 → **改写**原句（收窄条件、明确边界），不另起一条。
- **冲突**：新证据与已有规则矛盾 → 二选一：(a) 证据力悬殊，保留强方并删弱方；(b) 都成立，则合并为一条带条件的规则（"对上级时 X，对下属时 Y"）——这不是矛盾，是情境规则。
- **全新**：确实是新维度的洞见 → 新增，但先检查能否与既有句子合并压缩，为新句腾出字节。

每次合并后文件字节数**不应显著增长**；信息增加、字节持平是常态，信息不变、字节增长是失败。

## 三、措辞规则

- 删一切不改变预测的修饰语（"非常"、"某种程度上"、"值得注意的是"）。
- 用断言句，不用敷设句。写"批评触发切换叙事"，不写"当他面对批评的时候，往往可能会倾向于切换叙事"。
- 结构化优于成段：预测规则用 `情境 → 行为` 列表；机制解释才用短段落。
- 置信度不确定就标注（"置信度低，仅一例"），而不是用模糊措辞稀释断言。

## 四、字节预算（硬性校验）

写完必须运行校验，超预算就继续压缩，直到通过：

```bash
scapegoat profile budget <subject_id> --base-dir <base_dir> --strict
```

（或 MCP 工具 `profile_budget`。）默认预算：`profile.md` ≤ 6KB，每个 `analyse/*.md` ≤ 10KB；可在画像目录放 `budget.json`（`{"profile.md": 6144, "analyse": 10240}`）覆盖。

超预算时的压缩优先级（从先删到后删）：重复表述 → 多余案例 → 修饰语 → 弱证据低置信度条目。**不许为了过预算删掉高证据力的预测规则**——那种情况应上调 budget.json 并向用户说明。

## 五、结构约束

- 11 个 `analyse/*.md` 文件名固定不变（见 constants），每个文件保持既有小节结构：核心命题 / 机制 / 案例支撑 / 预测规则 / 稳定性。
- `profile.md` 只放各维度核心命题的索引式总览，不放案例，最后更新。
- 每次合并在文件头部维护一行来源记录：`<!-- sources: 语料N批, 访谈N轮, 测评N次; last: YYYY-MM-DD -->`，仅此一行，不写变更日志。
